# Profile Signal v0.4.0

ACTIVITY STREAMなどのlive-facing Widgetを、3時間ごとのフル集計から分離して**30分ごとに軽量更新**できるようにしたReleaseです。

## 主な変更

### Latest Signalsを30分更新へ分離

新しく `.github/workflows/profile-signal-stream.yml` を配布します。

このWorkflowは30分ごとに以下だけを更新します。

- LIVE SIGNAL
- CURRENT FOCUS
- ACTIVITY STREAM

TODAY、DEV PULSE、Repository Health / CI、Weekly / Monthly履歴、DEV RECAPなどの重い集計は従来どおり3時間ごとのフルWorkflowへ残しています。

### 不要なcommitを抑制

Latest Signals側は、公開GitHub Eventsから得られるlive-facing stateに実質的な変更が無い場合はREADME/stateをcommitしません。

ACTIVITY STREAMには最新Signal stateの更新時刻を表示します。

### Consumer設定を尊重

30分更新でもフルruntimeと同じ設定を使います。

- preset
- theme
- widget enable / disable
- `readme.path`
- profile timezone
- repository default branch

そのため、`terminal` / `minimal` themeや独自README pathを使うConsumerでも、3時間更新と30分更新で表示仕様が分岐しません。

### 重いAnalytics stateを保持

軽量更新では以下の既存stateを再集計・破棄しません。

- CI SIGNAL
- Repository Health
- DEV RECAP
- Weekly / Monthly history
- その他のフル更新由来state

live-facingな公開Event由来キーだけを更新します。

## 更新頻度

| Workflow | 既定頻度 | 主な役割 |
| --- | --- | --- |
| `profile-signal.yml` | 3時間ごと | 全体集計 / CI / History / 全Widget |
| `profile-signal-stream.yml` | 30分ごと | LIVE SIGNAL / CURRENT FOCUS / ACTIVITY STREAM |

GitHub Public Events自体に反映遅延が発生する可能性があるため、ACTIVITY STREAMはリアルタイム保証ではなく「GitHubから取得できた最新の公開Signal」として扱います。

## アップグレード

1. Assetsから `profile-signal-v0.4.0.zip` を取得します。
2. `.profile-signal/` をv0.4.0 runtimeへ差し替えます。
3. 既存 `.github/profile-signal.yml` は原則維持します。
4. `.github/workflows/profile-signal.yml` の差分を確認します。
5. 新しい `.github/workflows/profile-signal-stream.yml` を追加します。
6. `Profile Signal` を手動実行し、README / data / assetsのdiffを確認します。

アンインストール時は、`profile-signal.yml` と `profile-signal-stream.yml` の両方を削除してください。
